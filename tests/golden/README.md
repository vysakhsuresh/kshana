# tests/golden

Golden test vectors produced by independent, widely used Python reference
implementations so that Kshana's Rust crates can be checked against them.
They are generated by `scripts/golden/generate.py`, which runs completely
offline (no downloads at runtime).

## Reference libraries

| Library | Version | Role |
|---|---|---|
| Python | 3.13.16 | |
| numpy | 2.5.4 | |
| pyerfa | 2.0.1.5 (ERFA C library 2.0.1, SOFA release 20231011) | Earth attitude: ERA, GMST/GST, obliquity, nutation, precession (`frames.json`) |
| jplephem | 2.24 | Raw SPK Chebyshev evaluation of `data/de421.bsp` (`states.json`) |
| skyfield | 1.55 | Apparent positions, ecliptic of date, topocentric observer (`apparent.json`) |

Versions are also recorded in the `meta.versions` block of every JSON file.

## Commands

```sh
# one-time setup (any location outside the repo)
python3 -m venv /path/to/oracle-venv
/path/to/oracle-venv/bin/pip install numpy jplephem pyerfa skyfield

# generate (needs data/de421.bsp and data/finals2000A.all; see data/README.md)
/path/to/oracle-venv/bin/python scripts/golden/generate.py
```

Nothing is downloaded: Skyfield is pointed at the local kernel with
`skyfield.api.load_file(...)` and uses `load.timescale(builtin=True)` (its
bundled leap-second / delta-T tables); UT1-UTC is parsed from the local
`finals2000A.all`. Re-running the script reproduces the files byte for byte.

## Conventions shared by all files

* Two-part Julian dates are `[jd1, jd2]`: `jd1` is the half-integer JD of 0h
  UTC of the civil day and `jd2` the day fraction plus the UTC->TT (or UT1)
  offset, exactly the split produced by ERFA `dtf2d` / `utctai` / `taitt`.
  The epoch is `jd1 + jd2`.
* **TT is the authoritative epoch** of every record. The UTC ISO string is the
  input from which TT was derived with ERFA (`erfa.dtf2d('UTC')` ->
  `erfa.utctai` -> `erfa.taitt`); `tai_utc_s` records the TAI-UTC ERFA used.
  Before 1972 ERFA uses the historic "rubber-second" UTC (1961-1971) and
  TAI-UTC = 0 before 1960, whereas Skyfield's builtin table assumes 10 s before
  1972. Skyfield `Time` objects are therefore built from the ERFA TT JD via
  `ts.tt_jd(jd1, jd2)`, never from the UTC string. Tests should feed Kshana the
  TT (and, where given, UT1/TDB) two-part JDs directly.
* After the last known leap second (2017-01-01, TAI-UTC = 37 s) ERFA carries
  37 s forward; its "dubious year" warnings are suppressed by the script.
* Angles are radians in `frames.json` and degrees in `apparent.json`.
  Distances are km. Matrices are row-major `[[r00,r01,r02],[r10,..],[r20,..]]`.

## frames.json (24 records, ERFA)

One record per epoch, 24 epochs spread over 1950-01-01 .. 2050-12-31.

| Field | Produced by |
|---|---|
| `tt_jd` | `erfa.dtf2d('UTC', ...)` -> `erfa.utctai` -> `erfa.taitt` |
| `tai_utc_s` | `erfa.dat(y, m, d, fd)` |
| `ut1_jd`, `ut1_utc_s`, `delta_t_s`, `ut1_source` | see below |
| `era00_rad` | `erfa.era00(ut1_1, ut1_2)` |
| `gmst06_rad` | `erfa.gmst06(ut1_1, ut1_2, tt1, tt2)` |
| `gst06a_rad` | `erfa.gst06a(ut1_1, ut1_2, tt1, tt2)` |
| `obl06_rad` | `erfa.obl06(tt1, tt2)` (IAU 2006 mean obliquity) |
| `nut00b_rad.{dpsi,deps}` | `erfa.nut00b(tt1, tt2)` |
| `nut06a_rad.{dpsi,deps}` | `erfa.nut06a(tt1, tt2)` |
| `pfw06_rad.{gamb,phib,psib,epsa}` | `erfa.pfw06(tt1, tt2)` |
| `pnm06a` | `erfa.pnm06a(tt1, tt2)` (3x3, GCRS -> true equator & equinox of date; `r_true = pnm06a @ r_gcrs`) |

UT1: `data/finals2000A.all` carries UT1-UTC (columns 59-68, with the IERS
flag in column 58) only for MJD 41684 .. 61281 (1973-01-02 .. 2026-08-29 in
the copy used; later rows have an empty UT1-UTC field). For the 12 epochs
inside that range, `ut1_utc_s` is the linear interpolation between the two
bracketing 0h-UTC rows (both rows, their flags - all `I` = final - and the
interpolation fraction are recorded in `ut1_source.rows` / `fraction`), and
`ut1_jd = [utc1, utc2 + ut1_utc/86400]`. The script's parser was checked to
agree exactly with `skyfield.data.iers.parse_dut1_from_finals_all`, and the
resulting delta-T agrees with Skyfield's builtin table to < 1e-6 s. For the
12 epochs outside the file (the six before 1973 and the six after 2026),
`ut1_source.in_range` is `false` and UT1 = TT - delta-T with delta-T from
Skyfield 1.55's builtin `Timescale.delta_t_function` (IERS daily table
1973-2027, Stephenson-Morrison-Hohenkerk 2016 historic table and parabola
outside it); `ut1_utc_s` is then the derived `32.184 + TAI-UTC - delta_T`.
Either way the exact UT1 two-part JD that went into `era00`/`gmst06`/`gst06a`
is in `ut1_jd`, so a consumer can feed it in directly.

## states.json (12 records, jplephem)

Raw SPK type-2 Chebyshev states from `data/de421.bsp` at 12 TDB epochs
(1950-01-01 .. 2050-12-31), one entry per segment, with **no chaining** by the
library. Positions km, velocities km/s, ICRF/J2000 axes, relative to the
segment centre.

* `et_s`: TDB seconds past J2000 (JD 2451545.0 TDB), chosen so that
  `et = (JD_0h - 2451545.0)*86400 + seconds_of_day` is an exact integer.
* `tdb_jd = [2451545.0, et/86400]` are the two arguments passed to jplephem.
* Evaluation:
  `pos_km, vel_km_per_day = SPK.open(de421.bsp)[center, target].compute_and_differentiate(2451545.0, et/86400.0)`;
  `velocity_km_s = vel_km_per_day / 86400`. jplephem internally forms
  `(tdb - 2451545.0)*86400 + tdb2*86400` seconds, so the evaluation epoch is
  `et` exactly up to one rounding of `et/86400*86400`.
* `segments`: keys `399_rel_3`, `301_rel_3`, `3_rel_0`, `10_rel_0`,
  `1_rel_0` .. `9_rel_0` (`<target>_rel_<center>`).
* `derived`: explicit chains built by the script from the raw segments, with
  the formula recorded in each entry's `chain` field:
  `earth_rel_ssb = 3_rel_0 + 399_rel_3`, `moon_rel_ssb = 3_rel_0 + 301_rel_3`,
  `moon_rel_earth = 301_rel_3 - 399_rel_3`,
  `sun_rel_earth = 10_rel_0 - (3_rel_0 + 399_rel_3)`.
  `earth_rel_ssb` at J2000 was cross-checked against Skyfield's
  `eph['earth'].at(ts.tdb_jd(2451545.0))` (agreement 7e-9 km, velocity exact).

## apparent.json (20 records, Skyfield)

Apparent geocentric positions at 20 UTC epochs (1950-01-01 .. 2050-12-31) in
the **true ecliptic and equinox of date** for Sun (10), Moon (301), Mercury
(199), Venus (299) and the Mars .. Pluto barycenters (4-9), plus the
topocentric apparent Moon from Kochi (9.9312 N, 76.2673 E, 0 m).

* `t = ts.tt_jd(tt1, tt2)` with `ts = load.timescale(builtin=True)`;
  `skyfield_delta_t_s`, `skyfield_ut1_jd` and `skyfield_tdb_jd` record the
  time-scale values Skyfield used for the record.
* Geocentric: `lat, lon, dist = earth.at(t).observe(body).apparent().ecliptic_latlon(epoch='date')`
  -> `lon_deg` (0-360, east of the true equinox of date), `lat_deg`,
  `distance_km`. Also recorded: `lon_j2000_deg`/`lat_j2000_deg` from
  `ecliptic_latlon()` (epoch=None -> fixed ECLIPJ2000 frame) and
  `ra_date_hours`/`dec_date_deg` from `radec(epoch='date')`.
* Topocentric Moon: `(earth + wgs84.latlon(9.9312, 76.2673, elevation_m=0.0)).at(t).observe(moon).apparent().ecliptic_latlon(epoch='date')`.
  No refraction (ecliptic coordinates are never refracted in Skyfield) and no
  polar motion; the observer's rotation uses Skyfield's builtin delta-T.
* What "ecliptic of date" means in Skyfield 1.55 (verified in
  `skyfield/positionlib.py` and `skyfield/framelib.py`): `ecliptic_latlon(epoch)`
  with a non-None epoch calls `_Fake(self, epoch).frame_latlon(framelib.ecliptic_frame)`,
  and `epoch='date'` sets the frame time to the position's own `t`.
  `framelib.ecliptic_frame` is documented "Reference frame of the true ecliptic
  and equinox of date"; its rotation is
  `build_ecliptic_matrix(t) = rot_x(-(mean_obliquity(t.tdb) + d_eps)) @ t.M`
  where `t.M = N @ P @ B` (frame bias, IAU 2006 precession in the Capitaine et
  al. 2003 four-angle form evaluated at TDB, and the full IAU 2000A nutation
  evaluated at TT) and `d_eps` is the IAU 2000A nutation in obliquity. Note
  Skyfield uses plain IAU 2000A, not ERFA's `nut06a` (2000A with the IAU 2006
  rate adjustments); the difference is of order 0.1 mas.
* `apparent()` applies gravitational deflection by the Sun, Jupiter and
  Saturn (599/699 fall back to barycenters 5/6 in de421), Earth deflection
  for a topocentric observer, then aberration; refraction is never applied.

## swisseph.json (Swiss Ephemeris, Moshier mode)

Generated by `scripts/golden/generate_swisseph.py` with **pyswisseph 2.10.3.2**
(`swe.__version__` = `20230604`, `swe.version` = `2.10.03`) on Python 3.13.16.
No Swiss Ephemeris data files are needed or used: `swe.set_ephe_path('')` and
the built-in Moshier ephemeris (`FLG_MOSEPH`, tidal acceleration -25.58).

```sh
# one-time setup (the same venv as generate.py can be reused)
python3 -m venv /path/to/oracle-venv
/path/to/oracle-venv/bin/pip install pyswisseph

# generate (offline; reproduces the file byte for byte)
/path/to/oracle-venv/bin/python scripts/golden/generate_swisseph.py
```

Sections and record counts: `ayanamsa` 16, `houses` 12, `positions` 12,
`kp` 0 (swisseph has no KP sub-lord tables; the section is an empty list),
`sunrise` 3. Everything is in degrees / AU / days; the `meta` block repeats
the versions, flags and conventions.

**Time scales.** Every record holds the UTC input, `jd_ut` and `jd_tt` from
`swe.utc_to_jd(y, m, d, h, mi, s, GREG_CAL)` (returned as `(jd_tt, jd_ut)`),
and `delta_t_s = swe.deltat_ex(jd_ut, FLG_MOSEPH) * 86400`. Unlike the ERFA
files, swisseph's `jd_ut` is plain UTC treated as UT1 (no UT1-UTC) and its
leap-second table carries TAI-UTC = 37 s forward after 2017; before 1972 the
input is treated as UT1 and TT = UT + delta-T. Values computed "at jd_ut"
(ayanamsa, houses, sunrise) are therefore at UT1 = UTC of the record.

**ayanamsa.** For each epoch and each of `SIDM_FAGAN_BRADLEY` (0),
`SIDM_LAHIRI` (1), `SIDM_RAMAN` (3), `SIDM_KRISHNAMURTI` (5),
`SIDM_TRUE_CITRA` (27), after `swe.set_sid_mode(mode, 0, 0)`:
`get_ayanamsa_ut_deg = swe.get_ayanamsa_ut(jd_ut)` (relative to the *mean*
equinox, "without nutation") and `get_ayanamsa_ex_ut_deg =
swe.get_ayanamsa_ex_ut(jd_ut, FLG_MOSEPH)[1]` (relative to the *true* equinox
of date; the two differ by the nutation in longitude). The `_ex_ut` value is
exactly what swisseph subtracts from tropical longitudes under
`FLG_SIDEREAL` (verified: `positions[*].sidereal_lahiri.bodies.*.ayanamsa_applied_deg`
equals it to 1e-13). Both are evaluated at `jd_ut`.

**houses.** 12 (epoch, place) pairs: Kochi x3, London x2, Reykjavik (64.1 N,
outside the polar circle so every system is defined), Sydney x2, Quito,
Christchurch (-43.5), New York, and Tromsø (69.6 N) to exercise the
polar-circle behaviour. Per pair: `jd_ut`, `lat_deg`, `lon_deg`,
`sidtime_hours = swe.sidtime(jd_ut)`, `obliquity` from
`swe.calc_ut(jd_ut, ECL_NUT, FLG_MOSEPH)` (true and mean obliquity, nutation
in longitude and obliquity), and under `systems[h]` for h in
`P K R C B M T O E W` the result of `swe.houses_ex(jd_ut, lat, lon, h, 0)`
(tropical): `cusps_deg[12]` and the eight `ascmc` values (`ascendant_deg`,
`mc_deg`, `armc_deg`, `vertex_deg`, `equatorial_ascendant_deg`,
`coascendant_koch_deg`, `coascendant_munkasey_deg`, `polar_ascendant_deg`).
swisseph computes `armc = sidtime(true equinox) * 15 + lon` and all cusps
with the **true** obliquity (`obliquity.true_obliquity_deg`); the check
`(sidtime_hours*15 + lon_deg) mod 360 == armc_deg` holds exactly. Where the C
library would return retc = -1 with Porphyry cusps (Placidus and Koch inside
the polar circles) pyswisseph raises `swisseph.Error`; those entries carry
`error` and `undefined_at_latitude: true` instead of cusps (only Tromsø P
and K). Every successful non-Porphyry system is additionally compared with
'O' and flagged `fell_back_to_porphyry` (false everywhere in this file).

**positions.** 12 epochs 1950-2050. `bodies[name]` = `swe.calc(jd_tt, ipl,
FLG_MOSEPH|FLG_SPEED)` for Sun, Moon, Mercury .. Pluto, `MEAN_NODE` (10) and
`TRUE_NODE` (11): geocentric apparent (light-time, deflection, aberration)
longitude and latitude on the true ecliptic and equinox of date (tropical),
distance in AU, and the three daily rates; `retflags` is 260 (= flags). Note
the Moshier nodes: `MEAN_NODE` has zero latitude and `TRUE_NODE` the
osculating node. `sidereal_lahiri` repeats Sun and Moon with
`FLG_MOSEPH|FLG_SPEED|FLG_SIDEREAL` (65796) after
`set_sid_mode(SIDM_LAHIRI, 0, 0)`, together with `get_ayanamsa_ex_ut_deg` and
`ayanamsa_applied_deg = (tropical - sidereal) mod 360`.

**sunrise.** `swe.rise_trans(jd0, SUN, rsmi, (lon, lat, 0 m), atpress=0,
attemp=0, FLG_MOSEPH)` with `jd0 = swe.julday(y, m, d, 0.0)` (0h UT of the
civil date; the first event after `jd0` is returned) for Kochi on 2026-03-20
and 2026-10-15 and London on 2026-06-21. `atpress = 0` makes swisseph use
1013.25 mbar and 15 C. Three conventions are recorded for both rise and set:
`*_default` (`CALC_RISE` / `CALC_SET`: **upper limb with refraction**, which
corresponds to the Rust `kshana-events` convention of the Sun's centre at
-0 deg 50' = 34' refraction + 16' semi-diameter, to within swisseph's actual
refraction and semi-diameter values, i.e. a few seconds), `*_no_refraction`
(`| BIT_NO_REFRACTION`: upper limb, geometric) and `*_disc_center`
(`| BIT_DISC_CENTER`: centre with refraction). Each event has `rsmi`,
`result_code` (0 = found), `jd_ut`, `utc` from `swe.jdut1_to_utc` and
`revjul` = `[y, m, d, decimal_hour]` from `swe.revjul`.
