# Kshana on Android

A thin Kotlin/Compose shell over the Rust engine. The engine is compiled per ABI with
`cargo-ndk`; the Kotlin bindings are generated by UniFFI from `crates/kshana-ffi`. No
astrology or astronomy is written in Kotlin.

Status: the app has five doors written for a person with no astrology vocabulary, and
the full instrument behind them.

* **Today**: the day's headline, a sunrise-to-sunrise bar of good hours and hours to
  avoid, Sade Sati and the Jupiter/Saturn transits in one line each, the next exact
  moments, and the doors to Ask and Right time.
* **My life**: the plain-words reading (who you are, right now, eight life areas with
  "why" evidence and confidence per sentence, the next ten years), the 100-year life map
  with a scrolling timeline per area, and doors to the timing funnel, remedies and the
  chart.
* **Ask**: Prashna (three-tap picker, KP number, verdict and Moon windows).
* **Right time**: today's good hours, Muhurta for an activity, the observance calendar
  (Ekadashi, Pradosha, lunations, Sankranti with exact instants and observed days),
  and every exact moment; each row has a "Remind me" that schedules an exact alarm.
* **Me**: birth and certainty, Plain words / Astrologer switch, Family (any number of
  people on the phone), Compatibility (Ashtakoota out of 36, Mangal dosha both sides,
  synastry, in words), Baby name syllable, Glossary, Narration, and the instrument:
  Western chart, Vedic kundli (vargas, dashas, panchanga), Trust (self-test, error
  budget, export), Rectification, Settings.

Online is off by default and the app is complete without it. When switched on in
Settings: place search for any place on Earth (OpenStreetMap Nominatim), a refresh of
the IERS Earth-rotation file, and an optional narration of the computed reading from a
Claude model with the person's own key, grounded in the engine's sentences and told
not to add claims. Nothing else leaves the phone.

The sources are type-checked against the real Compose and Android framework classes with
`scripts/kotlin-check.sh` (Maven artifacts only, no SDK), but the APK itself has not been
built here because the SDK installer host is unreachable. Open `android/` in Android
Studio, run the steps below, and report any build error; the code targets AGP 8.7,
Kotlin 2.1, Compose BOM 2024.12.

## One-time setup

```sh
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
cargo install cargo-ndk
export ANDROID_NDK_HOME=~/Android/Sdk/ndk/<version>
./scripts/fetch-ephemeris.sh pypi            # data/de421.bsp + data/finals2000A.all
```

## Build the engine, bindings and kernel assets

```sh
./android/build-engine.sh
```

This produces `android/app/src/main/jniLibs/<abi>/libkshana_ffi.so`, the generated
`android/app/src/main/java/uniffi/kshana_ffi/kshana_ffi.kt`, and copies the kernel and
IERS file into `android/app/src/main/assets/` (all three are gitignored build outputs).

Then build the APK with Android Studio or `./gradlew :app:assembleDebug` from `android/`.

## How the app talks to the engine

```kotlin
val engine = Engine.open(spkPath, eopPath)        // once per process, see EngineProvider
val chart  = engine.chart(Instants.now(), 9.9312, 76.2673, 0.0,
                          HouseSystem.PLACIDUS, AyanamsaChoice.LAHIRI, false)
val next   = engine.nextEvents(Instants.now(), 14u, AyanamsaChoice.LAHIRI)
val chain  = dashaChain(chart.panchanga.moonSidereal, birth, Instants.now(), 5u)
```

Every record carries the provenance strings the UI shows, so the user can always see
which kernel, which UT1 source and which models produced a number.

## Ephemeris data

The app ships `de421.bsp` (17 MB, 1900–2050) inside the APK's assets and opens it from
the files directory. DE440s (32 MB, 1849–2150) replaces it when fetched from NAIF.
Nothing is computed on a server.
